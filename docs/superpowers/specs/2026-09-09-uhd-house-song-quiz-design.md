# UHD 하우스에서 들려온 노래 — 부스 태블릿 프로그램 설계

- 작성일: 2026-09-09
- 대상: 울산 HD FC 대학생 마케터 '프렌즈' 장외 부스 이벤트 / 부스 2
- 기획안 출처: `프렌즈 장외 부스 기획안.pdf` (5~6쪽)

## 1. 배경과 목적

'모여봐요 울산의 숲' 컨셉의 장외 부스 중 부스 2는 변조된 울산 HD 응원가를
듣고 곡을 맞히는 음악 퀴즈다. 기획안에는 진행 방법만 있고 실제로 곡을
재생하고 정답을 받을 도구가 없다. 이 문서는 그 도구 — 태블릿에 띄워놓고 쓰는
웹 프로그램 — 의 설계를 정의한다.

기획안이 정한 규칙 중 프로그램이 지켜야 할 것:

- 변조된 응원가 5곡 중 랜덤으로 1곡 재생
- 5초 내에 제시된 보기 중 정답 선택 (객관식)
- 정답 승점 3점, 오답 승점 1점

## 2. 범위

### 하는 것

- 응원가 1곡 랜덤 재생
- 보기 5개 제시 및 정답 판정
- 획득 승점(3점 / 1점) 화면 표시
- 인터넷 없이 동작
- 현장에서 재생 시간을 조절할 수 있는 숨은 설정 화면

### 하지 않는 것 (의도적 제외)

- **팀별 누적 승점 집계**. 기획안대로 승점은 스태프가 전입 신고서에 수기
  기록하고 화이트보드로 집계한다. 프로그램은 1인 1회 결과만 표시하고 끝난다.
  태블릿 새로고침이나 배터리 문제로 점수 데이터가 날아가는 위험을 만들지 않는다.
- 참가자 정보 입력, 로그 저장, 통계 내보내기
- 팀(노랑/파랑) 선택. 승점을 집계하지 않으므로 프로그램이 팀을 알 필요가 없다.

## 3. 운영 전제

| 항목 | 값 |
|---|---|
| 기기 | 태블릿(아이패드) 또는 노트북 1대 |
| 소리 출력 | 블루투스 스피커 1대 (기기 볼륨으로 조절) |
| 네트워크 | 없다고 가정. 오프라인 우선 |
| 조작 주체 | 참가자가 처음부터 끝까지 직접 터치 |
| 스태프 | 게임 설명 1명 + 승점 부여 1명 (기획안대로) |
| 1인당 소요 | 최대 약 20초 (재생 15초 + 응답 5초) |

## 4. 화면 흐름

화면은 상태 기계로 전환한다. 상태는 `idle` → `playing` → `answering` →
`result` → `idle` 네 개다. 설정 화면(4.5)은 상태가 아니라 현재 화면 위에
덮이는 오버레이이며, 닫으면 원래 상태로 돌아온다.

### 4.1 대기 (idle)

- 타이틀: "UHD 하우스에서 들려온 노래", 부제 "울산의 멜로디를 찾아라!"
- 큰 [시작하기] 버튼 하나
- 참가자가 이 버튼을 탭한다. 이 탭이 iOS/Safari의 오디오 자동재생 차단을
  푸는 사용자 제스처 역할을 겸한다. 별도의 "소리 켜기" 단계를 두지 않는
  이유가 이것이다.

### 4.2 재생 (playing)

- 선택된 곡을 최대 15초 재생한다.
- 보기 5개를 처음부터 화면에 띄우고 탭 가능한 상태로 둔다. 곡을 아는
  참가자는 3초 만에 눌러 즉시 결과로 넘어간다.
- 재생 중임을 나타내는 파형/음표 애니메이션과 함께 남은 재생 시간을
  표시한다. 이 표시는 재생 15초에 대한 것이고, 응답 5초 카운트다운은
  `answering`에 들어간 뒤에 별도로 크게 뜬다. 두 시간을 동시에 보여주지
  않는다.
- 15초가 지나면 음원을 멈추고 `answering`으로 넘어간다.

### 4.3 응답 (answering)

- 음원은 정지. 5초 카운트다운을 크게 표시한다.
- 5초 안에 보기를 탭하면 `result`로 간다.
- 5초가 다 지나도록 아무것도 누르지 않으면 **오답으로 처리**하고 `result`로
  간다. 기획안에서 오답이 1점이므로 무응답도 1점이다.

### 4.4 결과 (result)

- 정답: "정답!" + "승점 3점"
- 오답/무응답: "아쉬워요" + "승점 1점"
- 그 아래에 정답 곡명을 작게 표시한다.
- [다음 참가자] 버튼. 참가자가 누르면 `idle`로 돌아간다.
- 아무도 누르지 않아도 12초 뒤 자동으로 `idle`로 복귀한다. 참가자가 그냥
  자리를 떠도 다음 사람이 바로 시작할 수 있어야 한다.

### 4.5 숨은 설정 화면

타이틀 로고를 2초간 길게 누르면 열린다. 참가자가 우연히 들어가지 않을 만큼
숨기되, 스태프가 코드를 고치지 않고 현장 대응할 수 있게 한다.

- 재생 길이 조절 (기본 15초)
- 응답 제한 시간 조절 (기본 5초)
- 음원 5개 로드 상태 점검 (파일별로 정상/누락 표시)
- 캐시 새로고침 (음원을 교체 배포한 뒤 반영용)
- [닫기]

설정값은 `localStorage`에 저장한다. 날아가도 기본값으로 동작하므로 문제없다.

## 5. 문제 출제 규칙

### 곡 선택

5곡을 셔플해 한 곡씩 소진하고, 다 돌면 다시 셔플한다. 순수 랜덤과 달리 같은
곡이 연달아 나오지 않고, 5명이 지나가는 동안 5곡이 고르게 쓰인다.

셔플이 새로 시작될 때, 새 순서의 첫 곡이 직전에 나온 곡과 같으면 다시 섞는다.
바퀴 경계에서 같은 곡이 두 번 연속 나오는 것을 막기 위함이다.

### 보기

5곡 전체를 항상 보기로 표시한다. 표시 순서는 매 문제마다 섞는다.

### 채점

| 상황 | 승점 |
|---|---|
| 정답 선택 | 3 |
| 오답 선택 | 1 |
| 시간 초과(무응답) | 1 |

## 6. 곡 목록

기획안 5~6쪽 기준.

| # | 곡명 | 음원 파일 | 길이 |
|---|---|---|---|
| 1 | 잘가세요 | `audio/01-jalgaseyo.m4a` | 31.6초 |
| 2 | 우리가 살아가는 동안 | `audio/02-uriga.m4a` | 15.3초 |
| 3 | 홍하의 골짜기 | `audio/03-hongha.m4a` | 16.5초 |
| 4 | 별이 되어 | `audio/04-byeori.m4a` | 15.8초 |
| 5 | 끝까지 달린다 | `audio/05-kkeutkkaji.m4a` | 15.9초 |

파일명을 로마자로 두는 이유는 한글 파일명이 GitHub Pages 배포 시 URL 인코딩
문제를 일으킬 수 있어서다. 화면에 뜨는 이름은 위 표의 한글 곡명이다.

원본은 영상(mp4)으로 받았다. ffmpeg로 오디오 트랙만 그대로 복사해 꺼냈고,
재인코딩하지 않았으므로 음질 손실이 없다. 컨테이너만 바뀌어 확장자가 `.m4a`다.
AAC를 MP3로 다시 인코딩하면 이미 압축된 것을 또 압축하게 되고, 대상 기기가
아이패드라 AAC가 재생 호환성도 가장 좋다.

곡 길이가 재생 길이 기본값 15초와 거의 같다. 잘가세요를 뺀 네 곡이 15~16초
이므로, 설정 화면에서 재생 길이를 그보다 늘리면 곡이 끝난 뒤 무음이 흐른다.

### 음원 부재 시 동작

음원 파일이 아직 없다. 파일 로드에 실패하면 Web Audio로 생성한 데모음
(짧은 전자음 시퀀스)을 대신 재생한다. 목적이 둘이다.

1. 음원이 도착하기 전에도 전체 흐름을 완성하고 테스트할 수 있다.
2. 당일 파일이 하나 빠져 있어도 부스가 멈추지 않는다.

데모음이 재생 중일 때는 화면 구석에 작게 "데모 음원" 표시를 띄워 스태프가
알아챌 수 있게 한다.

## 7. 디자인

기획안의 "메인 컬러 파란 계열로 변경 예정"과 예시 배너 톤을 따른다. 구단
브랜드 중심으로 깔끔하게 가고, 숲 컨셉 장식은 넣지 않는다.

| 역할 | 값 |
|---|---|
| 배경 | 공식 블루 `#004098` |
| 패널·오버레이 | 짙은 블루 `#002B6B` |
| 포인트 | 골드 `#FFC72C` |
| 본문 | 흰색 `#FFFFFF` |
| 보조 텍스트 | `#B9CBE8` (배경 대비 5.8:1) |
| 정답 | 골드 강조 |
| 오답 | 밝은 청백색 `#DCE6F5` (배경 대비 7.5:1) |

배경색은 구단 엠블럼 이미지에서 직접 뽑은 값이다. 초기에는 예시 사진을
눈대중해 `#10265E`를 썼으나 엠블럼을 받아 정확한 값으로 교체했다.

오답 색을 밝게 잡은 이유가 있다. 처음 쓴 회청색 `#4A5B8C`는 배경 대비가
1.5:1밖에 되지 않아 "아쉬워요" 글씨가 배경에 묻혔다. 야외 부스에서 쓰는
화면이므로 정답/오답 구분은 색상 대비가 아니라 밝기 대비로 준다.

### 엠블럼

구단 엠블럼은 대기 화면 제목 위에만 넣는다. 재생 화면에도 작게 넣어
봤으나, 문제를 푸는 동안 시선이 분산되고 보기 5개가 이미 화면을 채워
브랜드 노출로 얻는 것보다 잃는 것이 많았다.

원본 PNG는 배경이 투명이 아니라 검정이므로, 네 모서리에서 플러드 필로
바깥쪽 검정만 지워 투명하게 만든 뒤 `img/emblem.png`로 넣는다. 이때 방패
바깥 검정 외곽선도 함께 지워지는데, 방패 안쪽 파랑이 배경과 같은 색이므로
흰 선만 남아 선화처럼 보인다. 의도한 결과다.

### 레이아웃

- 가로/세로 모두 대응한다. 가로에서는 보기 5개를 2열, 세로에서는 1열로 배치한다.
- 보기 버튼은 손가락으로 편하게 눌리는 크기(최소 높이 64px)로 크게 잡는다.
- 야외 부스이므로 대비를 높게 유지한다.
- Wake Lock API로 화면 꺼짐을 막는다. 지원하지 않는 브라우저에서는 무시한다.

## 8. 파일 구조

```
uhd-house-song-quiz/
├─ index.html
├─ css/style.css
├─ js/songs.js        5곡 데이터
├─ js/quiz.js         셔플, 보기 생성, 채점 (순수 로직)
├─ js/app.js          화면 전환, 오디오 재생, 타이머
├─ sw.js              오프라인 캐시
├─ manifest.webmanifest
├─ audio/README.md    음원 파일명 규칙
├─ test/quiz.test.js
├─ docs/superpowers/specs/
└─ README.md          현장 운영 매뉴얼 포함
```

### 모듈 경계

- **`songs.js`** — 곡 데이터만 내보낸다. 다른 파일에 의존하지 않는다.
- **`quiz.js`** — 순수 함수. DOM도 오디오도 모른다. 셔플 순서를 만들고,
  보기 배열을 만들고, 선택을 채점한다. 난수는 인자로 주입받아 테스트에서
  결정적으로 만들 수 있게 한다.
- **`app.js`** — 상태 기계, DOM 조작, 오디오 재생, 타이머, Wake Lock,
  설정 화면. `quiz.js`를 호출해 문제와 채점 결과를 얻는다.

`quiz.js`를 분리하는 이유는 이 부분이 유일하게 "틀리면 부스 운영이 망가지는"
로직이면서 브라우저 없이 검증 가능한 부분이기 때문이다.

## 9. 오프라인 동작

- 서비스워커가 첫 방문 때 HTML/CSS/JS/엠블럼을 캐시한다. 음원은 아직 파일이
  없으므로 개별 실패를 무시하며 따로 담는다. 파일이 들어오면 캐시 버전만
  올려도 통째로 캐시된다.
- 음원을 재생 시점에 담지 않는 이유가 있다. 브라우저는 오디오를 조각내서
  (Range 요청) 받는 경우가 많은데, 그렇게 온 206 응답은 Cache API가 저장하지
  못한다. 그대로 두면 경기장에서 음원만 빠져 데모음이 난다.
- 이후에는 네트워크 우선으로 응답한다. 인터넷이 되면 항상 최신 파일을 받고,
  안 되면 마지막으로 성공한 응답을 캐시에서 꺼낸다.
- 네트워크 응답을 4초까지만 기다린다. 경기장 와이파이가 죽지는 않았는데
  느리기만 한 경우가 제일 곤란하므로, 그 시간을 넘기면 캐시로 넘어간다.
- 처음에는 캐시 우선으로 만들었으나 되돌렸다. 배포한 수정이 새 워커가
  활성화된 '다음' 새로고침에야 반영돼서, 한 번만 새로고침한 사람은 계속
  옛날 화면을 봤다. 부스 준비 중에 문구 하나 고칠 때마다 겪을 문제였다.
- `manifest.webmanifest`는 홈 화면에 추가했을 때 주소창 없이 전체 화면으로
  뜨게 하는 용도다. 부스에서는 이렇게 띄우는 편이 참가자가 실수로 다른
  페이지로 나갈 여지가 적다.
- 캐시 버전 문자열을 두고, 음원 교체 배포 시 이 값을 올린다. 설정 화면의
  "캐시 새로고침"이 같은 일을 수동으로 한다.
- 서비스워커를 등록할 때 `updateViaCache: 'none'`을 준다. 이것이 없으면
  GitHub Pages가 `sw.js`에 붙이는 `max-age=600` 탓에 브라우저가 10분 동안
  새 워커를 받아오지 않는다.
- 부스 당일 절차: 경기장 도착 전 와이파이가 되는 곳에서 페이지를 한 번 열어
  캐시를 채운 뒤, 브라우저 탭을 닫지 않는다. README에 이 절차를 적는다.

## 10. 오류 처리

| 상황 | 동작 |
|---|---|
| 음원 파일 없음/로드 실패 | 데모음으로 대체, 화면에 "데모 음원" 표시 |
| 오프라인에서 음원 상태 점검 | 네트워크보다 캐시를 먼저 본다. 캐시에 있으면 실제로 재생되므로 "정상"으로 표시한다 |
| 오디오 재생이 브라우저에 차단됨 | 재생 없이 타이머만 진행하고 화면에 안내 표시. 퀴즈는 계속 진행 가능 |
| Wake Lock 미지원 | 무시하고 진행 |
| localStorage 사용 불가 | 기본 설정값으로 진행 |
| 서비스워커 등록 실패 | 온라인이면 정상 동작. 콘솔에만 기록 |

원칙은 하나다. **어떤 실패도 부스를 멈추지 않는다.** 실패하면 기능을 줄여서라도
다음 참가자를 받을 수 있는 상태로 되돌아간다.
